# Theming guide

The launcher executable has no design of its own. Everything you see in its window comes from a
`theme.json` the feed server publishes as a blob (`theme` in `/v1/status`). Until that theme is
downloaded, the launcher uses the neutral theme built into the executable
(`examples/theme-neutral/theme.json`).

- Schema: [`theme.schema.json`](theme.schema.json) (JSON Schema 2020-12). CI validates every
  theme under `examples/` against it; you can do the same with
  `pip install jsonschema && python3 tests/test_theme_schema.py`.
- Examples: `examples/theme-neutral/` (colours only, the embedded fallback),
  `examples/theme-demo/` (images, fonts, button states; generated by
  `tools/make-demo-theme.py`) and `examples/theme-showcase/` (launcher 0.3.0: transparent window,
  gradients, news list with filter tabs, options and language menus, image states by
  brightness; generated by `tools/make-showcase-theme.py`). The dev server in
  `examples/dev-server/` serves the demo theme.

## Structure

```json
{
  "schema_version": 1,
  "min_launcher_version": "0.1.0",
  "window":   { "width": 960, "height": 600, "background": {"image": null, "color": "bg"},
                "radius": 12, "draggable": true, "title": {"en": "My Game", "es": "Mi juego"} },
  "tokens":   { "bg": "#14171CFF", "primary": "#4F8CFF", "text": "#E8EAED" },
  "fonts":    { "body": {"family": "Segoe UI", "size": 14, "weight": 400} },
  "strings":  { "en": {"play": "Play"}, "es": {"play": "Jugar"} },
  "elements": [
    {"type": "button", "rect": [728, 500, 200, 56], "action": "play", "text": "play",
     "style": {"normal": {"fill": "primary", "radius": 8}, "hover": {"fill": "#6A9EFF"}}}
  ]
}
```

| Key | Meaning |
|---|---|
| `schema_version` | Required, `1`. Only an incompatible change would bump it; a launcher refuses a newer one and keeps its built-in theme. |
| `min_launcher_version` | Optional `X.Y.Z`. If it is newer than the running launcher, the launcher updates itself before using the theme. Use it when a theme relies on a feature older launchers do not have. |
| `window` | Size (64–4096 px, default 960 × 600), background colour and optional image (`null` = none), corner `radius`, `draggable` (drag the window by any spot without a button), `title` (per language, or one string for all), `transparent` (0.3.0, see below). |
| `tokens` | Named colours, reused anywhere a colour is accepted. |
| `fonts` | Named fonts: `family` (an installed font, or the family name inside `file`), `size` in pixels (6–200, default 14), `weight` (100–900, default 400), optional `file` (SHA-256 of a TTF/OTF blob). The font called `body` is the default for every element. |
| `strings` | Translations: language tag → key → text. |
| `elements` | What is drawn, in order: the first element is at the back. |

## Transparent window

Since 0.3.0, `"window": {"transparent": true}` makes the window per-pixel alpha: whatever the
theme leaves transparent shows the desktop, so a logo or a Play button can stick out of a frame
and the frame can have any shape. Default `false` (an opaque window with rounded corners).

- The window is still `width` × `height`; paint only the parts you want to see. Use a
  transparent background colour (`"#00000000"`, or a token with alpha `00`) and draw the frame as
  an element (a `text` box with `fill` or `gradient`, `border` and `radius`), or as an image with
  alpha.
- `radius` does not cut the corners in this mode: the alpha of the pixels does.
- Half-transparent pixels blend with the desktop. Fully transparent pixels let mouse clicks
  through to whatever is behind the window; dragging (`draggable`) works on every visible pixel.
- Launchers before 0.3.0 ignore the field and draw an opaque window: raise
  `min_launcher_version` to `0.3.0`.

## Coordinates

- Pixels, origin at the top-left corner of the window, `rect` is `[x, y, width, height]`, all
  non-negative integers. Width and height must be at least 1.
- They are logical pixels at 96 DPI (100 %), and so are the window size, font sizes, radii and
  border widths. The launcher scales everything to the system DPI (150 % at 144 DPI, 200 % at
  192 DPI) and draws images at the scaled size. If the scaled window does not fit in the screen's
  work area, the scale is lowered, even below 100 % (down to 25 %), so the whole window shows,
  centred in the work area.
- An element that sticks out of the window is clipped to it; one that starts outside is not
  drawn. Neither is an error.
- The window is not resizable and the theme is not scaled.

## Colours and tokens

- A colour is a token name, `#RRGGBB` (opaque) or `#RRGGBBAA` (alpha `00` = transparent,
  `FF` = opaque). Hex digits may be upper or lower case.
- Token values must be literal colours (a token cannot point to another token) and token names
  must not start with `#`.
- An invalid colour or unknown token never breaks the theme: the field keeps its default
  (transparent for `fill` and `border`, the `text` token for text, the `bg` token for the
  window background).
- Suggested token names, used by the defaults: `bg` (window background) and `text` (text).

## Texts, languages and variables

- An element's `text` is a **key** of `strings`. The launcher looks it up in the current
  language (the one chosen with a `language` button, saved in `.launcher/prefs.json`; else the
  Windows UI language, e.g. `es-MX`), then its base language (`es`), then `en`; if no language has the key, the
  key itself is shown. So `"text": "×"` simply shows `×`.
- Keep `en` complete: it is the fallback for every other language.
- Texts may contain variables, filled in by the launcher; unknown variables are left as they
  are:

| Variable | Where it has a value |
|---|---|
| `{days}` `{hours}` `{minutes}` `{seconds}` | `countdown` (time until the server opens; hours, minutes and seconds are two digits) |
| `{percent}` `{done}` `{total}` | download progress (`{done}`/`{total}` are human sizes such as `12.5 MB`) |
| `{version}` | the release version (a text using it is hidden while no version is published) |

- Keys the launcher itself uses (define them in `en` at least; see the neutral theme):

| Key | Shown |
|---|---|
| `status.checking`, `status.locked`, `status.ready`, `status.installing`, `status.error` | by `status` elements, according to the launcher state |
| `status.update`, `status.resume`, `status.no_release`, `status.offline`, `status.connection`, `status.install_failed`, `status.no_space`, `status.launch_failed`, `status.self_update`, `status.config`, `status.folder` | optional: replace the status line in those situations ([spec](spec.md#launcher-flow)); without them the launcher shows a built-in English text (`status.no_release`: "No version has been published yet.", shown in `ready` with Play disabled) |
| `news.empty` | by `news` and `news_list` elements when there are no news items (in the active category) |
| `news.category.<category>` | the tag of a `news_list` row for that category (e.g. `news.category.events`); without it the category itself is shown |
| `language.name` | the name of each language in the `language` menu, written in that language (`"Español"`); looked up only in that language, else the language tag is shown |
| `menu.repair`, `menu.open_folder`, `menu.game_settings` | the items of the `options` menu (built-in English fallbacks: "Verify and repair files", "Open game folder", "Game settings") |
| `status.repairing`, `status.repair_failed`, `status.settings_failed` | optional status lines: a repair in progress, a failed repair, a settings program that could not start (built-in English fallbacks) |

## Launcher states and `visible_when`

The launcher is always in one of these states:

| State | Meaning |
|---|---|
| `checking` | contacting the server, comparing files |
| `locked` | the server is not open yet (countdown running) |
| `ready` | everything is installed; Play starts the game |
| `installing` | downloading or applying an update |
| `error` | the server could not be reached or an update failed |

`visible_when` (a state or a list of states) shows an element only in those states; without it
the element is always shown. States this launcher does not know are ignored.

## Elements

Common fields:

| Field | Meaning |
|---|---|
| `type` | Required. One of the types below. |
| `rect` | Required. `[x, y, width, height]`. |
| `font` | Font name (default `body`). |
| `color` | Text colour (default token `text`). |
| `text` | String key (see above). |
| `align` | `left`, `center` or `right` (default `left`; `center` for `button` and `progress`). Single-line texts are vertically centred in `rect`. |
| `visible_when` | See above. |
| `style` | Interaction styles, see below. Any element may use `style.normal` for a background box. |

Types:

| Type | Draws | Own fields |
|---|---|---|
| `image` | an image blob scaled to `rect` | `image` (required SHA-256) |
| `text` | a text (or, with an empty `text` and a `fill`, just a box: panels are made this way) | — |
| `news` | the news of `/v1/status` (of the active category, see `filter`), one at a time: the image fills the rect except the last line (scaled to cover it, keeping proportions; what sticks out is cut, corners follow `radius`), the title is on that last line (two font sizes high); without image, only the title on the first line. Clicking opens its link | `interval`: seconds per item (1–3600, default 8; the first `news` element sets it) |
| `news_list` | the news (of the active category) as rows from the top of `rect`, see below | `row_height`, `tag_width`, `date_width`, `gap`, `date_format`, `tag_style` |
| `progress` | a bar: `track` is the empty part, `fill` the done part (a `gradient` replaces `fill`, see below); `text` (e.g. `{percent}%`) on top | — |
| `countdown` | `text` with the time variables, updated every second | — |
| `status` | the `status.<state>` string of the current state | — |
| `button` | a clickable box with `text` | `action` (required): `play`, `exit`, `minimize`, `open_url`, `filter`, `language`, `options`; `url` for `open_url` (`https://` only); `category` for `filter` |

Button actions:

| Action | Since | Does |
|---|---|---|
| `play` | 0.1.0 | installs or updates when needed and then starts the game; disabled while the launcher is `checking`, `locked`, `installing` or in `error` |
| `exit`, `minimize` | 0.1.0 | close (stopping a download, which resumes next time) or minimise the window |
| `open_url` | 0.1.0 | opens `url` (`https://` only) in the browser |
| `filter` | 0.3.0 | shows only the news whose category is `category` (required, at most 31 characters; `""` = all news) in every `news` and `news_list` element. The active filter button is drawn with its `selected` style. At start (and after a theme change that drops the active one) the active category is the first `filter` button's; without filter buttons every news item shows |
| `language` | 0.3.0 | opens a menu under the button with every language of `strings`, labelled by its `language.name` (else its tag), the current one checked. The choice changes texts, window title and news titles at once and is remembered in `.launcher/prefs.json` |
| `options` | 0.3.0 | opens a menu under the button: **repair** (`menu.repair`: checks every installed file against the release and downloads what differs, without starting the game; enabled in `ready` and `error`), **open game folder** (`menu.open_folder`: always enabled), and **game settings** (`menu.game_settings`: only listed when `launcher.json` has a `settings` program, see [spec](spec.md#launcherjson-next-to-the-executable-not-served); enabled in `ready`, `locked` and `error`) |

A button with an action this launcher does not know is not drawn, so `filter`, `language` and
`options` buttons need `min_launcher_version` `0.3.0` for older launchers to update first.

### `news_list`

```json
{"type": "news_list", "rect": [72, 216, 576, 280], "font": "row", "color": "text",
 "row_height": 40, "tag_width": 76, "date_width": 52, "gap": 12, "date_format": "news.date",
 "tag_style": {"fill": "accent", "color": "#FFFFFF", "radius": 8},
 "style": {"normal": {"radius": 10}, "hover": {"fill": "#EFEAFF", "color": "accent"}}}
```

Each row is `[tag] gap [title …] gap [date]`, one row per news item of the active category, in
the order of `/v1/status`; only whole rows that fit in `rect` are drawn.

| Field | Meaning |
|---|---|
| `row_height` | 8–512, default 40. Title and date are vertically centred in the row. |
| `tag_width` | 0–1024, default 0 (no tag column). The tag box is inset vertically by a sixth of `row_height` and is only drawn for items that have a category; its text is `news.category.<category>`, else the category. |
| `date_width` | 0–1024, default 0 (no date column). The date is right-aligned at the right end of the row; items without a date leave it empty. |
| `gap` | 0–256, default 12: space between columns. |
| `date_format` | A string key (so it can differ per language) or literal text with `{yyyy}`, `{mm}`, `{dd}`; default `{mm}-{dd}`. |
| `tag_style` | A style (`fill`, `gradient`, `color`, `border`, `border_width`, `radius`, `font`) for the tag box; starts from the element's `normal` style. |

- Title and date use the element's `font` and `color`.
- The row under the mouse is drawn with the `hover` style's `fill` (or `gradient`), `color` and
  `radius` behind that row only; while the button is down, with `pressed`. `normal` applies to
  the whole element (a `fill` there is a background for the list).
- Only rows with a link react to the mouse; a click opens the link.
- `news.empty` is shown when the active category has no items.

The news `category` and `date` come from `/v1/status` ([spec](spec.md#v1status)).

## Styles and states

```json
"style": {
  "normal":   {"fill": "primary", "color": "on_primary", "radius": 10},
  "hover":    {"fill": "primary_hover"},
  "pressed":  {"fill": "primary_pressed"},
  "disabled": {"fill": "disabled", "color": "on_disabled"}
}
```

- States: `normal`, `hover` (mouse over), `pressed` (mouse button down), `disabled`, and since
  0.3.0 `selected` (a `filter` button whose category is the active one). Only one applies at a
  time, in this order of priority: `disabled`, `selected`, `pressed`, `hover`, `normal` (a
  selected tab does not change on hover).
- Each state starts from `normal` and replaces only the fields it lists. `normal` starts from
  the element's `color` and `font`.
- Fields: `fill`, `color`, `border`, `border_width` (0–64), `radius` (0–2048), `track`
  (progress), `image` (SHA-256, drawn scaled to `rect`; `null` removes an inherited image),
  `font`, and since 0.3.0 `gradient`, `brightness` and `opacity`:

| Field | Meaning |
|---|---|
| `gradient` | `{"colors": [2–4 colours], "angle": 0–359}`: a linear gradient drawn instead of `fill`, colours evenly spaced. `angle` in degrees, default 90: `0` = left to right, `90` = top to bottom. `null` removes an inherited gradient. On `progress` it replaces only the done part, and spans the whole bar (the done part shows the colours its length reaches); `track` stays solid. |
| `brightness` | −100..100, default 0: darkens (negative) or lightens (positive) the images this element draws. |
| `opacity` | 0..100, default 100: makes the images this element draws see-through. |

- `brightness` and `opacity` apply to element images (a style `image`, an `image` element's
  image, news images), not to fills, text or the window background image. They let one image
  serve every state: `"hover": {"brightness": 15}`, `"pressed": {"brightness": -20}`,
  `"disabled": {"opacity": 50}`.
- Launchers before 0.3.0 ignore these fields (they draw `fill`, and images unchanged).

## Images and fonts

- Every image and font file is a blob addressed by its SHA-256 (lowercase hex), served by the
  feed server at `/v1/blob/<sha256>` and verified by the launcher. PNG with alpha is
  recommended for images.
- The launcher downloads every blob the theme references before drawing it, and caches them.
- Keep images at their display size: the launcher scales them to `rect` but does not crop
  (news images are the exception, see `news`).

## Previewing a theme

`launcher.exe --theme-preview <folder>` shows `<folder>/theme.json` without a server. Its blobs
are found by hashing every file in the folder and two levels of sub-folders, so images can keep
readable names. The launcher states cycle every few seconds with sample news, a countdown and a
growing progress bar. Options: `--preview-state <state>` holds one state, `--lang <code>`
picks the language (otherwise Windows'; the preview neither reads nor writes `prefs.json`). The sample
news have categories and dates, so `filter` tabs and `news_list` columns can be checked; the
language menu switches the language; the options menu lists every item (game settings included) but only opens
the folder. Without a folder it shows the built-in neutral theme. Problems (rejected
`theme.json`, missing blobs) appear as the status text.

## Limits

A launcher reads at most 64 elements, 32 tokens, 8 fonts, 8 languages, 128 strings per
language, 32 distinct blobs (images + font files) and 32 KiB of decoded text. Anything beyond is
ignored, not an error. 0.3.0 did not change them. A news category is at most 31 characters, a
gradient has at most 4 colours, and the launcher keeps at most 16 news items.

Since the first launcher that understood a feature matters to theme authors:

| Feature | Since |
|---|---|
| `window.transparent`; style `gradient`, `brightness`, `opacity`, state `selected`; `news_list`; actions `filter`, `language`, `options`; keys `news.category.*`, `language.name`, `menu.*`, `status.repairing`, `status.repair_failed`, `status.settings_failed` | 0.3.0 |
| `status.no_release` | 0.2.0 |
| everything else | 0.1.0 |

## Compatibility rules

- **Unknown is ignored.** Unknown top-level keys, element fields, style fields and states are
  skipped. An element of an unknown type, or a button with an unknown action, is not drawn; the
  rest of the theme is.
- **Additive changes keep `schema_version: 1`.** New element types, fields or actions are
  additions: older launchers ignore them. If the theme only works with them, also raise
  `min_launcher_version` so older launchers update first.
- **Only invalid JSON, a newer `schema_version` or a malformed `min_launcher_version` reject a
  theme.** The launcher then keeps its built-in theme.

## Adding an element type (launcher developers)

1. Add a value to `theme_element_type` in `src/core/theme.h`.
2. Write its parse function (`theme_type_parse_fn`): common fields are already parsed, it reads
   only its own ones, returns 0 to skip an unusable element. Put it in
   `src/core/theme_elements.c` or in its own file declared in `src/core/theme_internal.h`.
3. Add one line to the `TYPES` table in `theme_elements.c`.
4. Draw it in the window code, extend `docs/theme.schema.json` (an `if`/`then` block for its
   fields), this guide and `tests/test_theme.c`.
